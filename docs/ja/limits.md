# 制限、更新、利用条件 {#limits-updates-and-terms}

## 読まれないもの {#not-read}

- **誰が誰を倒したか、そして命中による兵士へのダメージ。** これらは武器とプレイヤーステートの遠隔呼び出しの命中結果（`HitResultsZeroBased`、`MulticastOnImpact.Hit`）に入っていますが、その構造は読んでいません。エンティティのサイドカーに、そのままの形で残しています。デコードしているのは被害者の体力だけです。
- **ボットのチーム。** ボットの状態は、チームかもしれない数値を持っています。確認されておらず、使っていません。
- **兵士が体の向きを超えて横を見ている場合。**

## ゲームの更新 {#game-updates}

このリーダーは、エンジンのリプレイ形式と、いくつかのSquadのクラス名・プロパティ名に依存しています。見えないプロパティの形式には依存しません。リプレイがそれらの名前を自分で持っているからです。

**Squadの更新で壊れうるもの:**

- **エンジンのアップグレード。** Squadは v10.4 で UE 5.7 に移りましたが、そこではテストしていません。アップグレードで、バンチのヘッダー、スポーンのデータ、`FRepMovement` が変わる可能性があります。これらは、段階がわかっている箇所で、コード上でバージョンごとに分けています。不明な段階（`ENG_PARTIAL_CUSTOM_EXPORTS`、末尾の移動ビット）は、v10.3.1 の動作に合わせています。
- **Irisのレプリケーション。** SquadがIrisに切り替えた場合、チャンク内のストリームは新しいものになり、このリーダーは読めません。Squad v10.3.1は従来のシステムを使っています（ReplicationGraphを動かしています）。
- **クラスやプロパティの改名。** Squadがプレイヤー、チーム、分隊のクラスやそのプロパティを改名した場合、名前やチームが欠けますが、位置は欠けません。
- **失敗したときの動作。** 形式が変わると、リーダーは診断に、ストリームのエラーや移動のエラーを出して大きく失敗します。静かに誤った位置を出すことはありません。`FRepMovement` は、そのビットがぴったり合う場合にだけ受け入れられます。

## 個人データ {#personal-data}

デモには、サーバー上の全員の名前とオンラインIDが入っています。テーブルとマッチドキュメントには名前が入り、IDは入りません。サイドカーは、すべてのプロパティのビットをそのまま保持するので、デモと同じようにIDを持ちます（デコードはしていません）。すべてをデモ自体と同じように扱ってください。
