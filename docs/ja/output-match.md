# 試合文書とサイドカー {#the-match-document-and-sidecars}

テーブルのほかに、各デモからは `<demo>.match.json` と、二つのサイドカー `<demo>.entities.parquet` と `<demo>.packets.parquet` が出力されます。ビューアは試合文書を、マッチタブで読みます。

## 試合文書 {#the-match-document}

`<demo>.match.json`（試合文書）は、最上位に `map`、`layer`、`level_path`、`game_version`、`engine_version`、`recorded_unix`、`duration_s`、`teams`、`squads`、`game_state`、`actors`、`players`、`rows`、`events`、`not_read`、`file`、`header`、`chunks`、`stream`、`shots`、`selfCheck` を持ちます（全項目: [コマンドリファレンス](../cli-reference.md)）。言葉で言えば、マップとレイヤー、ゲームとエンジンのバージョン、録画の時刻、長さ、そして:

- **チーム**: 番号、陣営、そしてその状態がレプリケートしたすべて（チケット、利用可能数、指揮官）を、変化するごとに。
- **分隊**: 番号、チーム、名前、作成者、リーダー、メンバー。
- **ゲームの状態**: サーバー名と設定、ゲームモード、試合の状態とID、マップとレイヤーのローテーション、投票、タイマー、今日のメッセージ。
- **アクター**: すべての乗り物、設置物、陣地、弾薬箱、ヘリコプター。クラス、どこで、いつスポーンしたか、いつ消えたか、誰のものか、そしてそのレプリケートされた状態（体力、ビルド状態、座席など）。
- **プレイヤーごとの1行**: 徒歩と乗り物でのサンプル、歩いた距離、遊んだ兵士のクラス、使った乗り物、チームの変更、取った座席、そしてプレイヤーステートがレプリケートしたすべて（ping、レベル、役割、現在の座席など）。ボットごとに1行。
- **出来事**の数、**プロパティの集計**（各クラスのプロパティが送られた回数）と**遠隔呼び出しの集計**、発砲と命中、**読まれなかった**もの、そしてリーダーの診断。
- **ファイルとヘッダー**: 情報ブロックとデモヘッダーのすべてのフィールド、チャンクの表、ネットフィールドのエクスポート表（`net_field_exports`）、チャンネルの閉じた理由、エクスポートが名前を与えないオブジェクトに見つかったクラス（`stream.class_resolution`）。
- **自己チェック**（`selfCheck.completeness`。[完全性](#完全性) を参照）。

オンラインID（Steam、EOS）は、意図して省いています。

変換したデモを軽く見るには:

```bash
python -c "import json; d = json.load(open('out/<map>/<demo>.match.json')); print(d['map'], d['layer'], d['duration_s'], len(d['players']))"
```

## 完全性 {#completeness}

このリーダーは、すべての3DHeat変換器が共有する規則に従っています。今読めるものはデコードし、残りはそのまま保持し、種類ごとにどれだけ扱ったかを示す（[コンバーターはすべてを保持する](https://github.com/Holdi601/3DHeat/blob/main/docs/converters.md)）。各試合文書には `selfCheck.completeness` があります。デモで出会った項目の種類ごとに、`seen`（見た）、`decoded`（完全にデコード）、`partial`（一部をデコードし、全体を保持）、`raw`（そのまま保持のみ）、`lost`（0でなければならない）の数です。種類は、リーダーが出会う場所で数えます: `file.info`、`chunk.<kind>`、`frame`、`packet`、`bunch`、`open`、`close`、`export.field`、`export.guid`、`external`、`property:<class>`、`rpc:<class>`、`block:<object>`、`subobject.*`。

読んだ実デモでは、`lost` は 0 です。項目数は数十万から数百万にのぼり、約半分は完全にデコードされ、残りは部分的またはそのまま保持されます。

**読まれるもの**（テーブルと試合文書に）:

- 情報ブロック、デモヘッダー（すべてのフィールド。わからない末尾の2バイトは16進数で保持）、チャンクの表。
- すべてのフレーム、パケット、バンチ（そのまま全体を、含むものに分けて）。開かれたすべてのアクター（スポーンの位置、向き、スケール、速度つき）と、閉じられたもの（理由つき: `Destroyed`、`Dormancy`...）。
- デコードできる範囲のすべてのレプリケートされたプロパティ（[プロパティのデコード](how-it-works.md#プロパティのデコード)）。`FRepMovement` とヘリコプターの移動コンポーネントからの位置、死傷、車両の体力、座席。
- 名前で示されるすべての遠隔呼び出し。デモが関数のグループをエクスポートしている場合は、そのパラメーターつき。発砲（`fire`）と車両への命中（`hit`）はテーブルへ。
- ネットフィールドのエクスポート表とネットGUID（その数。パスはエンティティのサイドカーにあります）。

**そのまま保持**（全体を、読んだ内容を横に添えて）:

- `<demo>.entities.parquet`。列は `time`、`type`（`<class>.<property>`、`<class>.<call>`、またはオブジェクトの名前）、`name`（アクターのクラス）、`entity`（アクターのネットGUID。テーブルの `entity` と同じ）、`kind`、`object`（サブオブジェクト）、`channel`、`handle`、`group`（エクスポートグループのクラスパス）、`decoded`（JSON）、`bits` と `payload`（ビット。下位から、バイト単位に埋めたもの）:
  - すべてのプロパティ更新（`kind` が `property`）。移動も含み、デコードできたものつき。何もデコードできない場合（名前のないハンドル、タレットの `RotationReplicatedMovement` のような構造、ビットのままのプロパティ）だけ、そのまま。
  - すべての遠隔呼び出しとカスタムデルタのフィールド（`rpc`）。関数のグループがエクスポートされていればパラメーターをデコード。されていなければそのまま（`RepInventory`、`PlayerStateData`）。
  - クラスが見つからなかったオブジェクトのすべてのコンテンツブロック（`block`: `Buoyancy`、`GameplayTasksComponent`、`AmmoRackComponent`...）。ヘッダーはデコード済み。
  - 開かれて閉じられたすべてのアクターのチャンネル（`open`、`close`）。削除または破棄されたすべてのサブオブジェクト。
  - 後のデコーダーがファイルだけで読むために必要な文脈: すべてのネットフィールドのエクスポート（`export.field`: グループのパス、ハンドル、プロパティ名、チェックサム）と、エクスポートされたすべてのネットGUID（`export.guid`: そのパス、外側、フラグ）。ストリームがそれらを与えた時刻で。
- `<demo>.packets.parquet`。列は `time`、`type`、`name`、`channel`、`offset`（ファイル内の位置）、`decoded`、`bits`、`payload`。情報ブロック、ヘッダーのチャンク、すべてのチェックポイントのチャンク（チェックポイントは、その時点での各アクターの状態。開始からのストリームにも含まれます）、すべての出来事のチャンク、そして読めなかったすべてのフレーム、パケット、バンチ（デモごとに1つのバンチ: 記録者自身の観戦者の、開かれたバンチ）。全体をそのまま。

エンティティの行は、`kind`、`type`、`entity` でまとめられ、それぞれ時間順です。ストリームの順にするには `time` で並べ替えてください。

**利用できないもの:**

- サーバーのデモが記録しないもの: クライアントの入力、プレイヤーが見たもの。
- クライアント側の効果: ヒットマーカー、音、キルフィードの文字（サーバーは呼び出しを送るのであって、その表示は送りません）。
- デコードされたオンラインID: ビットとしてのみ保持（[個人データ](limits.md#個人データ) を参照）。
